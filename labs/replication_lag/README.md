# 5.2 レプリケーションラグ

リーダー 1、フォロワー 3。フォロワーは「リーダーのログを何件まで見えているか」という整数だけを持つ。衝突解決もネットワークも使わない。遅れているフォロワーを 1 つ止めるだけで、ラグ由来の異常を再現する。

## モデル

書き込みはリーダーのログ末尾へ append する。読み取りはフォロワーへ行く。遅れは `Applied[i]` を手で止めて作る。

```go
type Write struct{ User, Text string }

type Cluster struct {
    Log     []Write
    Applied [3]int // 各フォロワーがログの何件まで見えているか
}

func (c *Cluster) Append(w Write)
func (c *Cluster) Read(follower int) []Write
```

ネットワークもゴルーチン間通信もまだ使わない。仮想時計は後から差し込む。

## 再現したい異常

1. **リードアフターライト** — 自分が書いたコメントが、遅れたフォロワーから読めない。
2. **単調読み取り** — 追いついたフォロワーのあとに遅れたフォロワーを読むと、時間が巻き戻る。
3. **一貫性のあるプレフィックス** — 返信が質問より先に見える。

1 と 2 は、このモデルのまま `Applied[2] = 0` のように止めれば再現できる。

3 は、適用が常にプレフィックスなら起きない。単一ログ + `applied` 整数では順序が保たれるため。再現するには、パーティションを 2 本にするか、適用順を崩せる実装に差し替える。それが本のポイントでもある。

遅れているフォロワーを固定しただけで、上記の異常が出ることが見えるテスト。
