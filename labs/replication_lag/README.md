# 5.2 レプリケーションラグ

普通の投稿・閲覧アプリの下で、レプリカが遅れる。手で `Step` して異常を再演しない。

## 今あるもの

- ストレージ: リーダーがログを持ち、フォロワーは `Step` で先頭から 1 件ずつコピーする（[`replica.go`](replica.go)）
- アプリ: `PostComment` はリーダーへ書く。`ViewThread` は指定されたフォロワーを読む（[`app.go`](app.go)）
- スケジューラ: シード付き乱数で、複製を進める／進めない、読み取り先を選ぶ（[`scheduler.go`](scheduler.go)）
- 不変条件: 同じユーザーが書いたあと、そのコメントが閲覧に無いとリードアフターライト違反（[`check.go`](check.go)）

```sh
go test ./labs/replication_lag -v
```

同じシードは同じ履歴になる。今のアプリはクラスタのフォロワーを直接読む。

## 次

対策はクライアント／セッション側に置く（書いた直後はリーダーから読む、スティッキー、位置まで待つ）。アプリの相手をクラスタからクライアントハンドルに変え、`Tick` を配送時刻つきのキューにする。分断やノード死は、それを壊す不変条件がテーマになってから載せる。
