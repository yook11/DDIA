# DDIA labs

[Designing Data-Intensive Applications](https://dataintensive.net/) を読みながら、本に出てくる異常を Go で再現する実験場。

本番の分散システムは作らない。複数ノード・書き込み・読み取り・遅れを手元でいじって、「いつ壊れるか / いつ壊れないか」をテストで見えるようにする。

## 約束

- 実験はプロセス内。実ネットワークや複数プロセスは、それがテーマになるまで使わない。
- 時間とレプリカの適用位置は外から止めたり進めたりできる。
- 書き込み経路や適用の仕方は差し替えられるようにする。同じテストが、実装を変えただけで通ったり落ちたりする状態を目指す。
- テスト名で「どの異常を見ているか」が分かること。
