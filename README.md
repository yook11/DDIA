# DDIA labs

[Designing Data-Intensive Applications](https://dataintensive.net/) を読みながら、本に出てくる状況を Go で再現し、どう対処するかを考える実験場。

本番の分散システムは立てない。普通のアプリとして書いて、遅れや読み取り先の当たり方の下で、ユーザーから何が壊れるかを見る。

## 約束

- 実験はプロセス内。実ネットワークや実 DB は、それがテーマになるまで使わない。
- アプリはラグを知らない。フォロワーを進めるのはシード付きのシミュレーションだけ。
- 同じシードなら同じ実行が再現すること。
- 対策は差し替えられること。同じ不変条件が、対策なしでは壊れ、対策ありでは守られること。
